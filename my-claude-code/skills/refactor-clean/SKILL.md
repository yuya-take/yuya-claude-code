# Refactor Clean

デッドコードを安全に検出・削除する。テスト検証を各ステップで行い、壊れたら即座に戻す。

## Step 1: デッドコード検出

引数 `$ARGUMENTS` で対象ディレクトリが指定されている場合はそこに絞る。なければカレントディレクトリ全体。

ファイル種別に応じてツールまたはGrepで未使用コードを検出する:

### Python
```bash
# 未使用import・変数・関数の検出
uv run ruff check --select F401,F811,F841 {対象ディレクトリ}

# 未使用コードの検出（vulture利用可能な場合）
uv run vulture {対象ディレクトリ} --min-confidence 80
```

ツールがない場合はGrepで検出する:
- 定義はあるがインポートされていない関数・クラス
- エクスポートされているが他から参照されていないもの

### TypeScript/React
```bash
# 未使用export・ファイル・依存の検出
npx knip

# 未使用npmパッケージの検出
npx depcheck
```

### Rust
```bash
# コンパイラ警告から未使用コードを検出
cargo build 2>&1 | grep "warning.*unused"
```

## Step 2: 検出結果の分類

検出されたデッドコードを安全度で分類する:

| 分類 | 例 | 対応 |
|------|---|------|
| **SAFE** | 未使用のユーティリティ関数、内部ヘルパー、テストヘルパー | 削除可 |
| **CAUTION** | コンポーネント、APIルート、ミドルウェア、メッセージキューハンドラー | 動的参照を確認してから削除 |
| **DANGER** | 設定ファイル、エントリーポイント、型定義、Pydanticモデル | 調査してから判断 |

分類結果をユーザーに提示し、削除対象の確認を得る。

## Step 3: 安全な削除ループ（SAFEアイテム）

SAFEに分類されたアイテムを1つずつ削除する:

1. **テスト実行** — ベースラインを確認（全テスト通過）
   ```bash
   # 対象サービスのディレクトリで実行（例: プロジェクトのテストコマンドに合わせて変更）
   make test                          # 例: make test, uv run pytest など
   ```
2. **デッドコードを削除** — Edit ツールで該当箇所を削除
3. **テスト再実行** — 削除後にテストが通ることを確認
4. **テスト失敗時** — 即座に `git checkout -- <ファイル>` で戻してスキップ
5. **テスト通過時** — 次のアイテムへ

## Step 4: CAUTIONアイテムの処理

削除前に以下を確認する:
- 動的インポート: `import()`, `__import__`, `importlib`
- 文字列参照: ルート名、コンポーネント名、メッセージキュートピック名での間接参照
- Docker Composeやスクリプトからの参照
- 他サービスからの依存（モノレポ内のワークスペース参照）

確認できたものだけStep 3と同じ削除ループで処理する。

## Step 5: 重複コードの統合

デッドコード削除後、以下を探す:
- ほぼ同一の関数（80%以上類似） → 1つに統合
- 重複する型定義 → 統合
- 何も追加しないラッパー関数 → インライン化
- 意味のない再エクスポート → 除去

## Step 6: フォーマット実行

削除・統合後にフォーマットを実行する:
```bash
# Python（例: プロジェクトの lint/format コマンドに合わせて変更）
make lint                             # 例: make ruff, uv run ruff check --fix など

# Frontend
npm run biome

# Rust
cargo fmt
```

## Step 7: 結果報告

```
## デッドコード削除結果

削除:   {N}件の未使用関数
        {N}件の未使用ファイル
        {N}件の未使用依存
スキップ: {N}件（テスト失敗またはCAUTION）
削減:   約{N}行削除

全テスト通過
```

## ルール

- **テスト実行なしに削除しない**
- **1つずつ削除** — アトミックな変更でロールバックを容易にする
- **不確実ならスキップ** — デッドコードを残す方が本番を壊すより安全
- **クリーンとリファクタを混ぜない** — このスキルでは削除のみ行い、書き換えは別で行う
